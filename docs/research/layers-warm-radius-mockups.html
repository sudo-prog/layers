The motion you asked for
Click Layers above. The menu does not drop from the button — it slides down from underneath the toolbar, over the stage. Three planes: toolbar z=2, menus z=1, stage z=0. The hidden state is translateY(-12px) — tucked up — so the open is a genuine slide out rather than a fade.

LAYERS — mockups in the warm-radius / glass style

Two references, both read before building. One is the Create flyout on a warm gradient with enormous corners and a translucent menu surface; the other is an ambient-sound tablet with a dense dark control panel beside an atmospheric visual. The style vocabulary is borrowed. The subject matter, the palette and the panels are LAYERS's own.

The borrowed vocabulary

  • Oversized radius at the top of the hierarchy. 52px on the shell, 32px on a surface, 24px on a card — then a normal scale below. This is the character of the reference, and it is the opposite of the SaaS-card kit where one radius is used everywhere.
  • A warm ambient field behind everything. The gradient is the page, not a panel. Every panel is a surface over it.
  • Genuine translucency. The reference menu surface is a dark glass where the orange shows through — that is what makes it read as glass rather than as a dark panel.
  • Dense control deck vs. atmospheric visual. A hard seam at 30/70, utilitarian on the left, dreamy on the right.
  • A menu that slides from underneath the plane. Already the established behaviour from the previous artifact.

The warm field

The gradient is the backdrop. Every panel must be opaque or glass over it — never text sitting directly on the gradient, where contrast is uncontrolled.

Glass, measured

The menu surface is rgba(20,10,8,0.72) with a 24px blur. At that alpha the orange field bleeds through to an effective brown of roughly #3A231B — dark enough for light text, warm enough to read as glass.

.menu-surface {
  background: rgba(20, 10, 8, 0.72);
  backdrop-filter: blur(24px) saturate(1.2);
}

The menu motion

The trigger row is z-index: 2, the menu band z-index: 1, the stage z-index: 0. The menu's hidden state is a translate, not an opacity, so the open animation is a slide out from underneath the plane.

.anim-menus { position: absolute; inset: 0; z-index: 1; }
.anim-menu  { transform: translateY(-12px);   /* tucked up */
              opacity: 0; visibility: hidden;
              border-top: 0;                  /* seam disappears */
              border-radius: 0 0 16px 16px; }
.anim-menu.is-open { transform: translateY(0); opacity: 1; visibility: visible; }

Where the menu band must live

It must be a child of the window and a sibling of every panel. Inside a stacking context it paints below that context's siblings; inside a backdrop-filter element it is consumed by the blur. Both of those bugs were found the hard way on the previous artifact, and both passed every geometry assertion — only reviewing the screenshot caught them.

What is deliberately not here

  • No SaaS-card kit: the radius is not one value everywhere.
  • No glassmorphism for its own sake — the translucency exists so the warm field shows through, not as decoration.
  • No emoji as icons, no feature-tile grid, no monument stat.
  • The atmospheric visual is generated in CSS gradients. The mockup is self-contained and has no image dependency.
